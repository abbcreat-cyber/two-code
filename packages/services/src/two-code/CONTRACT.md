# Two Code

唯一所有者是 TwoCodeCoordinator。它接收UI命令，管理角色归属、请求幂等、权限、事件和持久状态。原生框架保管模型上下文，Adapter必须以原生结算而非ACK确认完成。

ZCode通过V4会话帧投影本轮正文、思考、工具与终态，以sendText commandId关联turnHeader。已有会话使用Agent的prepareSessionExecution恢复执行能力/MCP并验证同一session身份；历史展示不再消费旧session响应。协议完整性、权限与取消边界见specs/two-code/zcode-v4-adapter.md。

桌面Host可通过TwoCodeBrowserExecutor注入已有内置浏览器端口。Step/Pi/Claude公开browser工具，以同一two-code任务scope操作Main拥有的标签页；只读和变更动作分别裁决，取消/换run后拒绝迟到结果。未注入则不公开工具，不改走外部浏览器；详见embedded-browser规格。

fork在源任务执行租约内从已成功回答边界创建新任务，主副手原生会话身份均独立，历史截断，权限/请求ID/分支用量清空，工作区文件不回滚。forkSource持久保存幂等来源；UI复用回答的叉子按钮。原生记录不能确认边界时显式失败，不用摘要代替原生上下文，见session-fork规格。

准入前拒绝通过原生调用ID关联notExecuted及verification.status=not-executed，不写进程退出码/输出。Claude的PreToolUse/canUseTool两个入口共享去重；后到消息不复活已拒绝工具。明确interrupted仅表示中断，不代表未执行或已回滚。主手回执和原工具详情使用同一事件日志，见collaboration-control规格。

主副手原生工具均提供check_text_encoding，经现有permission裁决，只读最多4MiB普通文件并返回编码/BOM/换行格式；不返回原文、不运行shell，格式事实不能代替业务验收。执行回执保留筛选后的警告行并明确未分离stdout/stderr，不能据缺少行断言stderr为空。用户明确指定的副手执行优先于默认正确性关键工作分工；主手仍负责口径与审查。会话路径守卫覆盖当前任务根目录，保留显式用户授权和原生视觉缓存例外。

tool_input记录原生参数生成进度，与tool（开始调用）、tool_end（原生完成）共享toolCallId。文件草稿预览最多20000字符，参数未完成不能视为执行成功。UI沿用原工具行，副手草稿保留在交接详情；开始派工时合并参数生成行，防止重复卡。流式过程及恢复均由同一事件日志投影，不把未知或中断标为成功。详见tool-input-progress规格。

verification事件保存原生命令工具的有界测试摘要和实际工具返回状态；不解析副手自述当作证据，不保留完整stdout或命令。read_sidekick将本次交接的回执和副手报告分开提供，不能用上一交接成功覆盖当前失败。工具completed不等于需求全部通过，reportedExitCode仅为输出中明确报告的值。见native-verification-receipts规格。

importImage将有界图片保存为Host持久附件，UI草稿仅保存引用及缩略图，发送复用原submit。两角色的view_image返回原生图像内容块；SVG由Host内置渲染，不依赖外部命令。模型image能力沿用原配置。Claude本机Messages网关的工具图片在本轮私有转发器中提升到同消息顶层image，保持工具配对，不改共享网关。详见specs/two-code/vision.md。

终态在适配器关闭、持久化和租约释放后广播，完成事件可立即接受续问；进入终态提交后的停止只等待提交，不倒改结果。TaskEvent可选toolCallId/notExecuted保存原生开场及权限门禁的明确未执行回执；普通工具失败和中断不代表未执行，旧事件无此字段仍可读取。

Step主手移植阶跃星辰1.0.10的提前开场流：原生同模型、无工具、有界短请求后沿用原档位主请求，一轮最多一次。两角色共享单一定义的沟通规则，副手不增加开场请求。来源、豁免、取消与验收见specs/two-code/opening-communication.md。

调用方经contract访问catalog/list/create/read/submit/cancel/respond及onDidChange。运行中submit作为补充要求交给当前主手，通过原生update入口接收；等待副手报告的主手会被唤醒，由主手决定是否更新同一副手。无更新能力时明确拒绝，送达不明时记录失败并停止旧计划；重复requestId复用准入结果，失败重试不能伪装成功。取消后显式续接保留角色会话。副手派工能力只注入主手，不允许跨任务或递归派工。读者不得把completed当作品质验收。

handoff、handoff_update、handoff_report及副手verification由同一任务事件日志保存逐字交接事实，handoffUserSeq指向已传递用户要求；两角色通过read_handoff_history按字符分页回读，保留原始seq、role、toolCallId和回执文本，不混入主手对话/回执。旧历史不补造缺失回执，旧成功不能替新交接背书。前端运行中补充保留当前工作轮及同一副手工具行，刷新从快照还原。副手工具表和owner权限均限制主手专有能力；availableTools仅为原生目录诊断，不作为权限裁决依据。

Claude运行中更新采用原生interrupt及流式用户输入，匹配user_message_uuid确认最终报告；Step/Pi采用原生steer。ZCode目前没有运行中更新入口。会话身份可续接，但不承诺任意shell状态或进程跨宿主重启保留；显式启动的后台服务由任务检查并复用。融合来源、适配边界和真实验收见specs/two-code/fusion-integration.md。

UI重开先读快照再消费单调序号变化。Host重启将未完成任务标为可恢复错误，禁止自动重跑。权限等待随取消结束；晚到结果不得覆盖取消。持久化失败必须显式报错。

运行中补充在原生更新确认排队后撤回准入前的主手待批准操作，以拒绝唤醒旧工具；不批准旧操作、不移除之后的新权限或无关副手权限，迟到旧permissionId返回失效。UI按同一任务permissions显示“待确认”与申请角色，刷新不保留已撤回的卡。工作目录按完整JSON字符串提供，空格不构成路径分隔。验收见specs/two-code/experience-refinement.md。

用户补充保存失败或副手update未确认均进入任务级错误并立即abort旧计划，主手不能通过捕获工具异常后读旧报告将任务标为完成。错误保存再次失败仍停止并显式报告；重复用户requestId沿用deliveryFailed结果。详见collaboration-boundaries规格。

技术端口和验收见specs/two-code/multi-harness.md。

Step Code以step-code标识接入同一Coordinator，执行本机step.exe原生RPC。step-api和step-plan保留不同provider身份，显示Step-5 API与Step-5订阅，模型ID仍为step-5-preview。只读导入配置，准入冻结后写角色私有目录。官方step-plan订阅同时导入Pi的OpenAI连接和Claude的Anthropic连接，保持独立harness身份，不导入API计费渠道，不改原生全局配置，详见specs/two-code/step-plan-cross-harness.md。执行前检查权限扩展已加载，Step/Pi的权限通道失败必须阻断工具。Windows原生powershell存在时直接启用，不能用Bash包装冒充。详见specs/two-code/step-code.md。

Pi/Step扩展UI按原生method分流：终端展示通知不创建权限，confirm才进入权限裁决；目前不支持的字符串交互取消并报错，禁止用布尔批准伪造用户答案。前端权限标题显示申请角色，工具参数仍复用原生预览。主副手指令约束重复验收及工具范围，但不替代权限所有者。

modelThinkingProfiles是已核实档位的固定快照，selectionThinkingProfile与normalizeThinkingSelection供UI和运行准入共享。Step-5两条渠道按本机原生能力快照提供low/medium/high，初始medium；旧关闭/极高值迁到原生边界。没有默认菜单项，已知模型归一为显式档位；未收录模型不猜选项。来源与更新日期见specs/two-code/official-thinking-levels.md。Pi模型能力与off/开启的协议映射只在适配层处理。缺省选择通过catalog的默认provider/model解析，模型切换必须传catalog才能正确识别真实上游别名。

ChatGPT套餐连接的公共authentication字段为chatgpt；凭据路径与令牌不出Host。EngineConnection.subscription携带冻结的专属agent目录、Node和代理，Pi原生OAuth共享文件锁负责刷新，角色session仍独立。固定官方端点不可经UI更改；测试连接也调用同一Pi原生授权链。

testConnection校验已保存连接及revision，用一次有界模型请求检测当前认证和响应；仅返回ok/message，不返回服务端错误正文或凭据。名称核验与请求连通性独立，UI不把路由元数据当成连通证据。

catalog模型项允许携带aliases和realModel。展示优先使用已解析目录名称，旧别名匹配到同一候选项；真实请求ID、provider及已有sessionId不因改名而修改。本机代理的上游名称仅从所配置loopback网关的只读路由元数据获取，不探测远程API；读取失败或路由不明时保留配置名称或请求ID，核验状态仅在管理页显示。

modelSettings/saveConnection/removeConnection及onDidCatalogChange由同一Host的TwoCodeConnections持有。原生文件只读，覆盖配置私有保存，revision防止过期覆盖。公共响应不包含密钥，空密钥保留旧值；运行准入冻结两角色连接，下次运行使用最新设置。统一管理入口复用原生模型设置页面。

TaskEvent.reasoning是脚手架实际返回的思考文本增量；空串仅表示当前思考块结束。Claude/Pi消费thinking_delta，ZCode消费原生model.streaming(reasoning_delta)。不生成替代思考，不合并到回答正文。UI投影为原生ReasoningRow，折叠与显示设置由原ZCode组件处理。sessionId持久化后立即广播，订阅者无需等第一段正文才能观察会话身份。

Pi/Step及Claude的文本和思考事件可携带blockId，投影按原生内容块合并，迟到思考尾包不能拆开一句正文。旧快照的紧邻思考标点兼容回并，不改写原事件。原生执行器在系统提示尾部提供真实工作区，副手交接复用相同事实；详细依据见stream-blocks与efficiency-quality规格。

configure({ taskId, preferences })在空闲时修改本任务的主副手模型、模式和单/双角色开关；与submit共用执行租约，同脚手架保留sessionId。configurePreferences只修改新任务默认值。旧快照模式默认为build，usage默认为空，不能估算旧token。

combinations/saveCombination/defaultCombination/removeCombination由JsonPreferences在同一个preferences.json内原子维护；revision防止多窗口覆盖，旧默认迁移为首套命名组合。选择复制配置到任务，不建立动态绑定；设默认只影响之后新任务，名称变更不修改任务。组合保存模型/渠道/思考/角色和权限模式，不含凭据。详见named-combinations规格。

组合最多10套，第11套提示先删除。界面以“副手：无”表达单模型，映射dual=false；不显示单/双角色开关及ZCode原生模式入口。关闭副手不销毁已有上下文，单模型组合不能覆盖休眠副手的底座；实际单模型执行不初始化副手、不注入派工工具。

EngineRun携带本轮mode和usage回执入口。Claude的工具前置钩子、Pi的tool_call扩展统一经过任务权限裁决；ZCode通过原生sendText的mode/planEnabled提交。按角色运行编号替换累计回执，避免分块与最终结算重复计费。UI只投影已采集用量，不把主副手contextWindow相加。

任务以two-code:<uuid>接入原生任务索引。Coordinator拥有执行事实，原生索引拥有重命名、置顶、分组、归档等组织元数据；展示投影保留这些元数据。前端复用原生SessionPane入口、ConversationTimeline、ChatPromptEditor、ModelConfigSelect和PermissionDialog，不维护第二份可选任务列表。后台投影在服务释放前收尾，查询期间收到的新事件优先于迟到快照。
