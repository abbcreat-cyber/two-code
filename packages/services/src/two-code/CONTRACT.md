# Two Code

唯一所有者是 TwoCodeCoordinator。它接收UI命令，管理角色归属、请求幂等、权限、事件和持久状态。原生框架保管模型上下文，Adapter必须以原生结算而非ACK确认完成。

终态在适配器关闭、持久化和租约释放后广播，完成事件可立即接受续问；进入终态提交后的停止只等待提交，不倒改结果。TaskEvent可选toolCallId/notExecuted保存原生开场及权限门禁的明确未执行回执；普通工具失败和中断不代表未执行，旧事件无此字段仍可读取。

Step主手移植阶跃星辰1.0.10的提前开场流：原生同模型、无工具、有界短请求后沿用原档位主请求，一轮最多一次。两角色共享单一定义的沟通规则，副手不增加开场请求。来源、豁免、取消与验收见specs/two-code/opening-communication.md。

调用方经contract访问catalog/list/create/read/submit/cancel/respond及onDidChange。运行中submit作为补充要求交给当前主手，通过原生update入口接收；等待副手报告的主手会被唤醒，由主手决定是否更新同一副手。无更新能力时明确拒绝，送达不明时记录失败并停止旧计划；重复requestId复用准入结果，失败重试不能伪装成功。取消后显式续接保留角色会话。副手派工能力只注入主手，不允许跨任务或递归派工。读者不得把completed当作品质验收。

handoff、handoff_update和handoff_report由同一任务事件日志保存逐字交接事实，handoffUserSeq指向已传递用户要求；两角色通过read_handoff_history按字符分页回读。前端运行中补充保留当前工作轮及同一副手工具行，刷新从快照还原。副手工具表和owner权限均限制主手专有能力；availableTools仅为原生目录诊断，不作为权限裁决依据。

Claude运行中更新采用原生interrupt及流式用户输入，匹配user_message_uuid确认最终报告；Step/Pi采用原生steer。ZCode目前没有运行中更新入口。会话身份可续接，但不承诺任意shell状态或进程跨宿主重启保留；显式启动的后台服务由任务检查并复用。融合来源、适配边界和真实验收见specs/two-code/fusion-integration.md。

UI重开先读快照再消费单调序号变化。Host重启将未完成任务标为可恢复错误，禁止自动重跑。权限等待随取消结束；晚到结果不得覆盖取消。持久化失败必须显式报错。

运行中补充在原生更新确认排队后撤回准入前的主手待批准操作，以拒绝唤醒旧工具；不批准旧操作、不移除之后的新权限或无关副手权限，迟到旧permissionId返回失效。UI按同一任务permissions显示“待确认”与申请角色，刷新不保留已撤回的卡。工作目录按完整JSON字符串提供，空格不构成路径分隔。验收见specs/two-code/experience-refinement.md。

技术端口和验收见specs/two-code/multi-harness.md。

Step Code以step-code标识接入同一Coordinator，执行本机step.exe原生RPC。step-api和step-plan保留不同provider身份，显示Step-5 API与Step-5订阅，模型ID仍为step-5-preview。只读导入配置，准入冻结后写角色私有目录。执行前检查权限扩展已加载，Step/Pi的权限通道失败必须阻断工具。Windows原生powershell存在时直接启用，不能用Bash包装冒充。详见specs/two-code/step-code.md。

Pi/Step扩展UI按原生method分流：终端展示通知不创建权限，confirm才进入权限裁决；目前不支持的字符串交互取消并报错，禁止用布尔批准伪造用户答案。前端权限标题显示申请角色，工具参数仍复用原生预览。主副手指令约束重复验收及工具范围，但不替代权限所有者。

modelThinkingProfiles是官方档位的固定快照，selectionThinkingProfile与normalizeThinkingSelection供UI和运行准入共享。没有默认菜单项，已知模型归一为显式档位；未收录模型不猜选项。来源与更新日期见specs/two-code/official-thinking-levels.md。Pi模型能力与off/开启的协议映射只在适配层处理。

ChatGPT套餐连接的公共authentication字段为chatgpt；凭据路径与令牌不出Host。EngineConnection.subscription携带冻结的专属agent目录、Node和代理，Pi原生OAuth共享文件锁负责刷新，角色session仍独立。固定官方端点不可经UI更改；测试连接也调用同一Pi原生授权链。

testConnection校验已保存连接及revision，用一次有界模型请求检测当前认证和响应；仅返回ok/message，不返回服务端错误正文或凭据。名称核验与请求连通性独立，UI不把路由元数据当成连通证据。

catalog模型项允许携带aliases和realModel。展示优先使用已解析目录名称，旧别名匹配到同一候选项；真实请求ID、provider及已有sessionId不因改名而修改。本机代理的上游名称仅从所配置loopback网关的只读路由元数据获取，不探测远程API；读取失败或路由不明时保留配置名称或请求ID，核验状态仅在管理页显示。

modelSettings/saveConnection/removeConnection及onDidCatalogChange由同一Host的TwoCodeConnections持有。原生文件只读，覆盖配置私有保存，revision防止过期覆盖。公共响应不包含密钥，空密钥保留旧值；运行准入冻结两角色连接，下次运行使用最新设置。统一管理入口复用原生模型设置页面。

TaskEvent.reasoning是脚手架实际返回的思考文本增量；空串仅表示当前思考块结束。Claude/Pi消费thinking_delta，ZCode消费原生model.streaming(reasoning_delta)。不生成替代思考，不合并到回答正文。UI投影为原生ReasoningRow，折叠与显示设置由原ZCode组件处理。sessionId持久化后立即广播，订阅者无需等第一段正文才能观察会话身份。

configure({ taskId, preferences })在空闲时修改本任务的主副手模型、模式和单/双角色开关；与submit共用执行租约，同脚手架保留sessionId。configurePreferences只修改新任务默认值。旧快照模式默认为build，usage默认为空，不能估算旧token。

EngineRun携带本轮mode和usage回执入口。Claude的工具前置钩子、Pi的tool_call扩展统一经过任务权限裁决；ZCode通过原生sendText的mode/planEnabled提交。按角色运行编号替换累计回执，避免分块与最终结算重复计费。UI只投影已采集用量，不把主副手contextWindow相加。

任务以two-code:<uuid>接入原生任务索引。Coordinator拥有执行事实，原生索引拥有重命名、置顶、分组、归档等组织元数据；展示投影保留这些元数据。前端复用原生SessionPane入口、ConversationTimeline、ChatPromptEditor、ModelConfigSelect和PermissionDialog，不维护第二份可选任务列表。后台投影在服务释放前收尾，查询期间收到的新事件优先于迟到快照。
