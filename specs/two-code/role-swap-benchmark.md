# Step Plan与Claude GLM主副互换对比

目标是比较同一组模型在两种角色配置下完成相同代码任务的协作可靠性和效率。A为Step Code step-plan/step-5-preview medium主手、Claude Code glm-5.3 max副手；B互换角色，模型、渠道和档位不变。不修改生产默认组合、不使用Flash替代GLM-5.3、不创建额外代理。

复用固定coding-fixtures的小、中、长任务和同一验收器。小任务修复uniqueNames；中任务交付CSV/整数金额汇总/CLI三个模块；长任务在同一主副手session分四轮增加库存纯逻辑、持久化与CLI、过期和汇总、README与回归。每档A/B同时运行在不同目录，按小→中→长推进，最多两任务同时活动。提示只含必要的工作目录差异，验收器源码hash必须一致且运行中不被修改。每阶段300秒预算；失败且任务仍可继续时最多一次相同规则的外部修复反馈。不得因方向不同给予不同重试机会。

通过同一服务公开API调用真实原生底座，观察事件与原生工具回执。用户明确要求按日常使用方式测试，两组统一mode=yolo（完全访问），不增加编辑模式的测试审批。主手确定接口/派工/审查，副手实现并以各自原生PowerShell执行规定验证命令，主手不重复验证。测试仍使用隔离工作目录，需求限制联网、依赖安装及无关文件修改；这些是任务范围，不宣称完全访问具有文件沙箱。

记录每阶段及总耗时、第一次实际测试是否通过、失败测试次数、外部修复轮数、交接/报告次数、相同源码重复通过验证、未执行工具回执、工具错误、usage和原生模型身份。未执行不能计为实际测试，固定ledger由验收器独占；执行回执与账本不一致应单列配合问题。代码测试通过与配合问题分别记录，不通过时保留原始证据。每阶段会话ID不变、跨任务会话独立；主手必须在交接后消费副手报告。

状态仍由TwoCodeCoordinator持有；验收器只消费公开API与落盘记录，不增加产品状态或运行分支。若遇到真实适配缺陷，先保留失败矩阵，修复后重新做对称受影响验收，不能把不同版本结果直接当模型速度比较。最终结论仅适用于本机、本渠道、本档位与本轮样例；每档仅一对样本，不声称统计显著或普遍优劣。

关闭并释放所有所属任务后保留精简结果、模型产物与测试hash，清理临时目录及双方可能持有的Claude原生会话。正式配置不变。清理不能假定Claude永远是副手。

## 初轮审批干扰与模式调整

基线role-swap-1791731186837误按edit模式设计精确审批，Step副手的powershell经Two Code批准后又出现原生`Approve powershell [调用ID尾缀]`确认，验收器拒绝此不同形式的请求，B组无法验证。此基线停止并保留，不纳入模型效率结论，也不外推为用户完全访问模式的故障。

收到用户明确指示后，两组改为完全访问并对称重跑。原生confirm沿用既有Two Code完全访问权限路径，不为此基线额外修改底座参数或放宽生产权限策略。编辑模式下二次审批和泛化拒绝回执单列为本轮未修复的边界观察；本次比较聚焦用户实际模式。

完全访问实测还发现，模型会发出列目录等非测试命令，或把Windows路径交给WSL工具导致测试程序尚未启动就失败。因此仅将固定验收器PASS/FAIL标记对应的原生回执与独立ledger计数核对，其余命令回执、工具错误仍分列保留。不能因普通命令数多于测试账本，就判为产品丢回执；原始运行统计保留，最终comparison追加复核后统计。

为补全交付对比，全部预期阶段的代码已经通过、但仅主手交付超时的任务，两组均可获得一次最多300秒的原会话续接。保留initial-results和initialOutcome，不重置已花时间，不新增实现需求；续接耗时加到累计执行耗时，单列externalContinuations，排除等待其他样例结束的测试调度闲置时间。不把这类需额外续接的交付称为首次完成。源码发生变化必须有对应新验证，不能复用旧hash的通过记录。

## 完全访问实测中的退出码格式

Step无论担任主手还是副手都出现将Windows路径送入WSL/run_command的调用偏差。曾尝试加强默认shell说明，但真实补测glm-coordination-1791733506085仍选错工具，并追加echo片段；随后自行改成Linux路径才完成。该提示试验未作为有效修复发布，原始失败保留。只读原生工具探测确认PowerShell在已配置工具清单中；不能把模型选择问题说成底座没有该能力，也不能声称已消除此类错误。本次不偷偷重写模型命令、不移除用户可用的WSL工具。
