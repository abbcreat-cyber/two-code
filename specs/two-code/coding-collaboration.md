# 写代码协作分档验收

用户要求从常用功能回归转向小、中、长代码任务。固定Step Code step-plan/step-5-preview主手和Claude Code DeepSeek副手，三档并行，全部在D盘独立QA项目，不改用户业务仓库、不联网、不安装依赖、不操作鼠标。

小任务为单模块uniqueNames修复；中任务为CSV解析/金额汇总/CLI三个模块；长任务为库存预留工具四阶段：纯业务模块、JSON持久化和CLI、过期预留与汇总、最终交付和全量验证。长任务复用同一主副手原生session，阶段输入逐步补充；不是用一次极短问答冒充长任务。

预置check.mjs及输入文件由验收器持有，模型不能修改；每次验证由原生PowerShell执行确切的本地Node命令。模型编写和调试源码，主手审查关键文件与副手回执。check输出PASS/FAIL并在.qa/ledger.jsonl记录阶段、实际源码指纹和验证结果。协调器仍拥有任务、权限和交接状态，验收器只观察及裁决自己创建的测试任务。

```text
固定接口/测试 → 主手判断 → 唯一副手实现 → 原生验证回执 → 主手审查
                  ↑              ↓
              下一阶段 ← 通过且session/回执/产物一致
```

判定边界：代码错误先交回同副手修复，最多一次追加的测试驱动续问；不能把测试失败自动说成Two Code缺陷。框架问题包括任务/角色串用、交接丢失、回执与真实执行次数不符、阶段续接更换原生上下文、状态假完成。保护测试指纹，副手验证结束后不由验收器重复执行同一测试。小轮最多180秒，中轮300秒，长每阶段300秒；超时取消本验收拥有的任务并保留证据。报告分别记录代码验收与协作检查，不因最终状态completed就宣称功能正确。
