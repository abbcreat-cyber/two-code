# 原生验证回执减少重复核对

目标是减少“副手已跑过测试，主手却把结果当作纯口述而重复运行或误报未验证”的往返，同时保留主手对产物的必要审查。固定Step Plan/Claude DeepSeek high，不降档、不更换模型。

适配器把原生命令工具结果投影为有界verification事件：真实toolCallId、工具名、工具完成/失败/中断状态、输出中明确报告的退出码reportedExitCode（有才提供）和少量测试摘要。不把模型报告解析成执行证据，不保存完整命令/原始stdout/图片数据；包含凭据字段的行排除。输出中打印的EXITCODE不冒充原生进程退出字段，回执缺少退出码就不猜0，工具调用结束不等于所有需求通过。

Coordinator仍拥有唯一事件日志。read_sidekick只返回本次交接期间该副手的原生回执与模型报告，二者明确区分；不同交接/任务不串用旧证据。前端沿用副手工具详情，不新增居中面板。主手依据已存在的实际验证结果避免重复运行；用户明确要求独立再测或改动影响结果时仍要验证。

候选实测虽然缩短用时，仍有一次主手拿到成功回执后尝试额外执行。曾试验澄清“正确性关键工作主手亲自运行”与“副手执行、主手审查”的文案边界，但该试验耗时回升且未消除重复尝试，因此撤回文案，只保留可客观验证的原生回执机制。此机制改善证据传递，不宣称已经保证模型永不重复验证。

```text
副手原生命令结果 → 适配器提取安全摘要 → 同任务事件日志
                                        ↓
                    read_sidekick 原生回执 + 副手报告 → 主手核对关键产物
```

验收：相同金额修复小任务进行串行基线和候选重复测试，记录完成用时、工具次数、重复执行及独立函数验收。另测失败回执不能伪装成功、取消后不能引用旧成功、敏感输出不进入摘要，并用真实底座验证事件确实来自tool_result。

## 回执输出边界

执行摘要保留有界WARN/WARNING/ERROR及中文警告/错误行，继续排除凭据字段；退出0仍是工具成功，不等于没有警告。回执标明只保留筛选摘要，未保留stdout/stderr分流，主手不得将没有某行当成stderr为空的证明。

2026-10-12四脚手架矩阵中，Step原生run_command首轮混入WSL UTF-16警告，返回文本在换行与`PASS: all coding checks`之间含NUL；原摘要正则因此漏识别真实通过行。只在摘要/退出码解析视图移除NUL，保留原生日志，不改变工具状态、不推测缺失退出码、不尝试还原已损坏的警告中文。清理后仍执行凭据行过滤，NUL分隔的敏感字段也不能进入摘要。矩阵进程继续运行固定0.8.26，修复回归与后续实测单列，不重写原比较结果。

## 文本字节检查

实测CSV格式验收出现四次search_files及将文本搜索称为字节级验证。两角色新增只读check_text_encoding工具：沿用当前工作区相对路径和既有权限口径，直接读取最多4MiB普通文件，仅返回实际读取字节的UTF-8有效性、BOM及LF/CRLF/独立CR计数（无效UTF-8不猜文本换行）。不返回原文，不运行shell，不修改文件，不常规追加到所有任务；用户要求编码/换行或需要字节证据时使用一次。模型仍需审查文件内容和业务结果，格式事实不证明业务正确。试验中的长度/SHA-256会诱发无关文件检查及手工字节计算，正式接口移除这两个字段，避免扩大验收范围。

唯一事实来源是一次文件读取的字节快照，摘要通过原生工具结果交给调用者，不新增业务缓存或事件类型。文件随后变动会使证据过时，不把旧摘要当当前文件证明。拒绝目录、超限和权限拒绝，取消时停止，不静默降级为文本搜索。单测覆盖中文、BOM、混合换行、非法UTF-8、超限和拒绝；真实CSV任务验收工具被调用、内容正确且主副手分工正确。

## 连续任务的证据恢复

`read_handoff_history`与`read_sidekick`必须读取同一份Coordinator事件日志。交接历史保留副手的verification事件、原始seq/at/toolCallId和已脱敏的text，按事件顺序与对应交接并列；角色字段明确来源。历史不重新解析或压缩回执，不截掉早于最近8条的证据，不包含主手verification及普通对话。旧快照没有回执时保持缺失，不能从副手报告补造。分页仍为20000字符及nextOffset，双方读同一规则。

历史回执只证明发生过的那一次执行；后续输入或产物变化时不能据旧成功宣布通过。即时read_sidekick仍只引用当前交接回执，完整历史不替代当前轮状态，不增加第二份缓存或自动重复验证。

```text
原生回执 → Coordinator唯一事件日志 → 持久化/恢复
                                 ├→ read_sidekick：本次交接最近8条
                                 └→ read_handoff_history：逐字分页含历次副手回执
```

验收增加：真实成功/失败小任务各执行一次，再让主副手读历史并生成receipt.md，独立验证实际执行次数、原始回执标识、失败状态、固定模型及原副手会话复用。回归覆盖多次交接、超过8条回执、跨页逐字恢复、隔离主手事件和旧快照兼容。只测这些边界，不声称已模拟原生上下文压缩。
