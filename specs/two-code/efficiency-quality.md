# 更快完成与更高质量

用户要求以任务完成用时及产物质量为目标，不以新增检查数或功能数作为优化指标。固定Step Plan主手、Claude DeepSeek high副手，不降低档位、不偷偷换模型、不删除必要验收。

## 对比方法

同一脚本、同一输入与验收条件、新建隔离工作区、每组顺序执行三种小任务：冻结金额呈现、带退款与字符串金额的代码修复、SVG裁切修复。计时从submit前到协调器终态，包含底座启动和清理；另外记录输出token、交接次数、工具调用及报告长度。独立检查实际文件/函数行为，视觉题必须由主手实际view_image，不能仅相信模型说完成。

小样本受模型服务延迟、缓存和采样影响，只报告观察结果，不把一次更快当作普遍加速保证。若某项变慢或失败也保留。脚本不把答案写入系统提示；同题输入一致，只更换运行协作策略。

## 运行策略

用户明确分工高于默认“正确性关键工作由主手执行”。数据口径、公式、边界条件和产物审查仍归主手；当用户点名副手整理/转换/统计文件时，主手先明确规则，然后一次交接让副手执行和保存产物，不能用数据量小或该默认规则作为自行代做的理由。未明确分工时仍按风险选择主手直接处理或委派。不缩短整个角色规范、不更换模型、不增加额外模型轮次或权限弹窗。

对派工路径的确定性守卫覆盖整个本任务会话目录，避免只拦connection而放过session根目录写文件。用户明确指定的会话路径、真实工作区本身位于该目录内，以及适配器生成的lead/visual与sidekick/visual图片缓存仍允许；不拦同前缀的其他目录。不静默改写路径，返回真实工作区让主手修正。任务事件与权限仍只有Coordinator一个所有者。

Step/Pi每轮第一次成功的文件读取/目录查询结果附上执行器确认的相对路径基准，说明默认查找的返回路径相对此目录；不把配置目录视为工作区。只补一次来源事实，不替换工具原结果、不在失败时补造成功，不声称显式指定其他搜索根的结果也相对此目录。这样在结果被使用时纠正基准混淆，不只在初始提示或错误派工后提醒。

试验过把完整角色规则压缩为中文短版，但三个任务的输出token和用时没有稳定改善（修复题还明显变慢），因此撤回该候选，不把“提示词更短”当作加速证据。保留完整xuexi角色结构，仅澄清与用户明确分工冲突的默认规则，并在交接末尾明确简短证据报告、减少重复报告；仅实际发生运行中更新时附加中断状态提醒。

小任务默认一次完整交接→副手执行并提供最窄证据→主手一次核查关键产物→直接交付。有真实独立工作才非阻塞；不用预热派工、轮询、目录确认或重复验收。简单交接与回报短而完整，复杂任务按风险展开，不硬截断报告。副手不为用户沟通单独增加过程长文；主手仍保留开场和重要进度。修正反馈一次列齐，失败时保留实际证据并有界重试。

Coordinator状态和工具权限仍是唯一事实来源。此次策略调整不改变权限模式、路由、模型档位、图片像素传递或完成时序。

## 分工提醒的时机

真实SVG任务出现主手先改正确、收到工具完成后的分工提醒，再回滚并交副手重做。将用户明确分工的提醒提前到原生before_agent_start：启用副手时，用户指定副手执行的修改或命令应在主手实施之前派工。工具完成后只说明已经实际执行以及保留正确产物的原则，不再用重新分派的口吻追责。仍须真实报告实际执行者；用户明确要求撤销、重做或产物有错时照常修改，不能拿“保留产物”掩盖错误或绕过用户要求。

适配器只提供运行时提示，不增加权限规则、自动回滚、缓存或第二套分工状态。保留每轮最多一次成功编辑后提示、单角色不提示、失败编辑不提示的边界。验收用同一SVG题观察文件最终内容、真实工具顺序、主手独立看图以及是否出现为了补分工而回滚重做；用时波动与指令遵循分别记录。

实测发现主手把agent配置目录当工作目录，导致副手搜索不存在路径、写错目录被拒绝并返工。原生before_agent_start最后提供执行器确认的工作区，并在副手交接开头提供同一事实；相对路径直接使用该目录，不用搜索确认。增加的是运行时事实，不静默改写模型的文件参数。

继续实测证明，仅提示仍可能重复把本轮lead/connection/agent当工作区。现增加owner派工前检查：brief引用本轮主/副手connection配置目录且用户未明确要求该目录时，尚不启动副手，返回准确工作区要求主手修正；视觉缓存路径和用户明确指定的配置检查不拦。这样在错误派工前纠正，避免让副手绕路搜索、尝试错误写入再来回解释。
