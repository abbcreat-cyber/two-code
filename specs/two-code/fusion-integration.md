## 约束

Coordinator拥有任务、交接事实、权限、取消和报告接收状态。Native adapter只传递原生消息和回执。前端不另存被接受的输入队列。手工模型切换和当前全局默认偏好继续保持；不让资料的原版配对表覆盖用户明确选择。副手获得当前任务限制，但不获得主手完整聊天；中文输出、后台操作以及原版工具位置继续保持。

```text
用户补充 → Coordinator保存并派给主手 → 唤醒等待中的主手
                                      ↓ 判断
                              同一副手收到lead_update
                                      ↓ 原生回执
逐字事件账本 ← brief / report ← 主手读取证据并审查
```

## 验收要求

模型规范之外的边界必须有工具/owner回归；运行中更新必须用真实底座验证，不以提示词含有interrupt宣称完成。真实小任务覆盖一次执行与一次验证、冻结输入不重算、完整批量修正、权限阻塞、历史跨续接、运行中更新与同一会话身份。不能把同一副手重新启动为第二个并发实例。功能成熟度和未实现的底座能力在最终记录中明确列出。

## 实测修正

冻结数据呈现任务中，主手把相对输出文件错误展开到工作区父目录，权限拒绝后又把原因升格为“所有Write不可用”。保留权限边界，不放宽写入范围；拒绝回执明确携带当前工作区、请求目标、模式，并区分主手专有能力。指导先核对真实路径，不把单次拒绝或既有警告当成环境整体损坏。Claude移除冗余MCP bare allowedTools，统一保留PreToolUse/owner裁决，避免原生SDK重复发出callback-shadowed警告。

交接工具的渲染ID也加入taskId，避免不同任务相同事件序号共享工具展开状态。用户运行中补充仍属于当前工作轮，不能把旧副手卡标成停止或丢弃其后到达的报告。补充传输失败持久记录并停止旧计划，重复requestId仍返回同一失败，不伪装送达；旧交接迟到的更新不得影响后续交接。

原生工具目录实测额外暴露Workflow、ListAgents、PushNotification、ScheduleWakeup、CronCreate/CronDelete和ReportFindings。它们从Claude副手工具表移除，owner同步拒绝对应名称；不是只加一句“不许调用”。实际工具目录作为可选诊断事实保存，不作为授权来源。

桌面运行中更新实测：夹具已写started.txt，原生interrupt阻止了后续late.txt，但副手把中断回执解读为“从未启动”，主手复述该结论。更新信封和报告审查提醒必须明确：中断不代表未执行、更不代表回滚；没有原始执行证据时只报告已中断以及未确认的既有影响，不补造输出、退出码或耗时，也不为查明这些而擅自扩大工具范围。
