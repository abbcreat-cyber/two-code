# 原生界面功能与双模型适配

目标是让可见入口具备真实行为，不修改模型回答质量。文件/目录加入对话、工作区文件拖入、输入历史、Esc停止复用现有UI机制；图片仍走现有附件服务。服务只接受现有submit/cancel，不新增执行通道。

确认的缺口：TwoCodeSessionPane未注册文件树加入对话事件、未启用工作区拖入、未传promptHistory、未注册原生Escape停止；附件菜单仍提供不支持的goal/workflow及@/$/快捷提示；登录后的云分享按钮修改原生分享状态，但双模型页面不消费该状态。

规则：
- 文件树加入/拖入复用原生文件mention，跨工作区使用绝对路径；只是插入引用，发送后由模型原生工具读取。不自动执行或上传文件。
- 全局加入对话和Esc只作用于focused且非readOnly的窗格。Esc先让菜单/弹窗消费，不把关闭浮层当作停止。
- 输入历史从本工作区已保存的用户事件派生，最多30条，连续相同文字去重。回填只恢复文字，不自动重新附图；刷新后仍可使用。
- 不支持的原生目标、工作流、插件/技能快捷菜单不再显示，包括输入框始终挂载的原生SlashCommandPlugin；图片入口保持可用。手输普通文本不作伪命令执行，原生会话仍默认启用自己的命令面板。
- 云分享依赖原生会话协议，暂不接入；按用户要求直接隐藏双模型分享按钮，不触发分享状态。编辑历史并回滚文件暂不开放。分叉已按用户新增要求接入主副手原生上下文，见session-fork规格。

```text
文件树/拖入 → 当前可编辑窗格 → 原生mention → 现有submit → 原生文件工具
任务用户事件 → 历史投影 → 输入框上下键（发送仍由用户触发）
Esc → 原生浮层守卫 → 当前运行任务cancel → Coordinator停止双方
```
