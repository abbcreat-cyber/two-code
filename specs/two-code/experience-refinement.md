# 固定双底座整体体验验收

目标组合为Step Code / step-plan / step-5-preview主手与Claude Code / DeepSeek V4.1 Flash high副手。测试在D盘隔离目录，通过真实本机底座和服务/API进行，桌面交互使用不聚焦的后台验收窗口，不操纵物理鼠标。

## 0.8.4发现的权限等待死锁

实测目录`D:/Apps/TwoCode/qa/experience-live-1791695294468`：主手powershell申请权限时用户发送“撤销命令，改为副手写文件”，submit返回成功且用户补充已进入事件日志，但旧权限卡未撤销，10秒观察内始终阻塞。原生steer是排入当前工具之后，无法自动替用户决定旧权限。

Coordinator仍是唯一权限和输入所有者。已接受的运行中补充将挂起的主手待批准操作视作需要重新判断；原生更新确认排队后，撤回该次准入前已存在的主手权限请求，不替用户允许，也不清除更新之后的新请求。副手权限继续由主手是否更新该副手决定，不能因为无关补充直接撤销其他角色操作。未支持或未确认送达的更新沿用明确失败/停止语义。

```text
用户补充 → owner保存输入及旧权限ID → native steer确认排队
                                   ↓
             owner移除旧请求并以拒绝唤醒原工具 → native处理补充
                                   ↓
                        单调事件广播 → 原权限卡撤下
```

迟到的旧permissionId批准必须返回已失效。新的主手工具仍照常申请权限。前端从同一任务快照投影权限列表，刷新和订阅不能保留已撤销卡；不增加第二个前端权限队列。

原版底部状态位置在存在权限请求时显示“待确认 · 主手/副手”，无权限时仍显示“执行中”；沿用权限卡、输入框、工具行位置和紧凑字体，不新增中间浮层。

打包版实测旧命令确实未执行，权限卡60ms撤回，但原工具活动未显示拒绝结果。权限扩展的确定性block回执添加内部标识，适配层在原生tool_execution_end解析为既有toolCallId/notExecuted事件，前端更新同一原版工具行“未执行：本次操作未获批准”；普通执行失败不能被误判为从未执行，原生中断也不使用该标识。

同批账单题暴露路径理解错误：主手将真实末级目录“中文 目录”截为“中文”，随后额外list/find，甚至尝试未获允许的pwd。原生工具收到的参数已经被截断，证实不是底座文件API去掉了空格。由owner将已核实工作目录按JSON字符串明确注入，优先当前目录相对路径；明确指定副手的任务先交接，不自行做未要求的目录探测。失败不能靠放宽命令权限解决。

## 验收范围

- 等待主手权限时改向：旧命令未执行，旧卡移除，同一主手继续派工，新产物核对正确。
- 中文和空格路径，批量修改两个产物，冻结已核实结果不重算，副手会话复用。
- 文件不存在后的准确报告，补齐输入后在原会话恢复，不把工具失败说成成功。
- 重复输入、迟到批准及更新失败用本地回归覆盖；真实任务在最终安装包验证显示和持久回放。
