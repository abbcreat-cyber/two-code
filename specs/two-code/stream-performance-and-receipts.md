# 流式性能、工具回执与角色用量

## 已确认事实

用户报告的卡顿任务包含 10,318 条思考增量。Coordinator 每条事件都 structuredClone 完整历史并广播，UI 每个快照重投影全部事件。修复目标是限制派生快照开销，不伪造模型完成、不自动重试、不删除思考和既有历史。

## 单一所有者与时序

`适配器事件 → Coordinator 立即追加完整事件 → 快照发布器合并通知 → UI 展示`

执行事实仍由 Coordinator 持有。发布器仅保存任务引用和待发计时器，每任务最多一个待发快照。正文/思考/参数增量首包立即发送，其后最多每 100ms 发布一次；状态、审批、工具边界、错误和终态立即发布并清除旧待发快照。关闭服务清除计时器，取消后不能出现迟到 running 快照。全量历史、seq、blockId、分叉边界与最终存储不变。

## 界面

- 原生工具成功仅在紧凑工具行显示勾号与“已完成”，不再渲染“原生工具已完成”的灰色输出块。保留真实失败/中断说明；参数默认折叠，展开时按 JSON 格式显示，长内容局部滚动。
- 主手与副手各有独立 Token 入口和数据面板，即使未调用也保留完整面板并显示未调用与 0；已调用但无回执显示未上报与破折号，单模型也保留副手历史。每个面板展示本角色输入/缓存读写/输出明细；脚手架模型标明“当前配置”，不冒充历史用量的唯一模型归属。旧数据缺失不推算。
- 一切分项来自现有 RunUsage.role；主副手累计和等于总量；只统计收到的回执，运行中标注已上报。

## 验证

回放真实事件测快照次数与耗时；突发/持续流、即时审批、取消/结束冲刷、dispose 无迟到通知。回放原任务 UI，验证长思考不会产生上万 DOM 行。混合角色用量和缺失回执测试；深浅主题工具行及 Token 面板截图。
